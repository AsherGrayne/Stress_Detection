STRESS DETECTION PROJECT - IMPLEMENTATION HANDOFF FOR GEMINI
============================================================

Purpose of this file
--------------------
This text file documents exactly what was changed and how the new implementation works.
It is written so another AI model, such as Gemini, can understand the current project
without needing the previous chat history.


High-level change
-----------------
The project originally had:

1. Python FastAPI inference service for the ML model.
2. Spring Boot Java backend.
3. Flutter frontend.

The user requested that Flutter and Spring Boot be removed and replaced with a lighter,
easier-to-run, professional-looking implementation.

The new implementation keeps the existing Python ML inference service and replaces both
the Spring Boot backend and Flutter frontend with a single Node.js application:

1. Python FastAPI inference remains in:
   inference_service/main.py

2. New lightweight Node.js app lives in:
   node-app/

3. Node.js app does all of this:
   - Serves the browser dashboard.
   - Exposes REST API endpoints.
   - Reads simulated telemetry from balanced_data.csv.
   - Reads real telemetry from Firebase.
   - Calls the Python inference API at /predict.
   - Keeps rolling chart data in memory.
   - Optionally logs mild/high stress events to MongoDB.

4. Removed old implementation folders/files:
   - flutter_app/
   - spring-backend/
   - docker/Dockerfile.spring
   - FLUTTER_BACKEND.md

--------------------

node-app/src/server.js
----------------------
This is the main replacement for the old Spring Boot backend and also serves the frontend.

Key responsibilities:

1. Load configuration from environment variables.
2. Read balanced_data.csv for simulated telemetry.
3. Maintain current telemetry snapshots in memory.
4. Maintain rolling time-series chart data.
5. Poll Firebase for real device telemetry.
6. Call Python inference service.
7. Provide REST API endpoints.
8. Serve static frontend from node-app/public.
9. Optionally log mild/high stress to MongoDB.


Configuration inside server.js
------------------------------
The config object uses:

PORT
  Default: 8090
  Controls the Node app port.

STRESS_CSV_PATH
  Default: root balanced_data.csv
  Used for simulated telemetry.

STRESS_INFERENCE_BASE_URL
  Default: http://127.0.0.1:8081
  Python inference service URL.

STRESS_INTERVAL_MS
  Default: 5000
  Scheduler interval for simulated and real telemetry.

STRESS_CHART_HISTORY_SIZE
  Default: 60
  Number of chart points retained per sensor.

FIREBASE_URL
  Default:
  https://stress-detection-c2bec-default-rtdb.asia-southeast1.firebasedatabase.app/data.json
  Used for real device telemetry.

MONGODB_URI or STRESS_MONGODB_URI
  Default: empty
  If provided, enables MongoDB logging.


CsvFeed class in server.js
--------------------------
Purpose:
  Replacement for the old Java CSV telemetry feed.

Behavior:
  - Reads balanced_data.csv synchronously at startup.
  - Skips the header row.
  - Converts each row into:
    {
      sequenceIndex: number,
      reading: { x, y, z, eda, hr, temp }
    }
  - Uses an internal cursor.
  - next() returns the next row.
  - When the end is reached, it loops back to the beginning.

CSV expected columns:
  X,Y,Z,EDA,HR,TEMP,label

The label column is not used by Node inference. The prediction comes from the Python model.


TelemetryState class in server.js
---------------------------------
Purpose:
  Replacement for the old Java in-memory telemetry state.

Behavior:
  - Stores the latest snapshot for one source.
  - Keeps rolling chart series for:
    X, Y, Z, EDA, HR, TEMP
  - Each chart point has:
    { t: epochMilliseconds, v: sensorValue }
  - Limits the number of points to STRESS_CHART_HISTORY_SIZE.

Snapshot shape returned to frontend:
{
  "observedAt": "ISO timestamp",
  "sequenceIndex": number,
  "reading": {
    "x": number,
    "y": number,
    "z": number,
    "eda": number,
    "hr": number,
    "temp": number
  },
  "predictedStressCategory": number,
  "predictedStressLabel": "No Stress | Mild Stress | High Stress",
  "series": {
    "X": [{ "t": number, "v": number }],
    "Y": [{ "t": number, "v": number }],
    "Z": [{ "t": number, "v": number }],
    "EDA": [{ "t": number, "v": number }],
    "HR": [{ "t": number, "v": number }],
    "TEMP": [{ "t": number, "v": number }]
  }
}


StressLogStore class in server.js
---------------------------------
Purpose:
  Replacement for the old Java MongoDB stress log service.

Behavior:
  - If no MongoDB URI is configured, it logs a warning and disables persistence.
  - If MongoDB URI is configured, connects using the official MongoDB Node driver.
  - Uses database:
    Stress_Detection
  - Uses collections:
    stress_log_simulated
    stress_log_real
  - Logs only category >= 1:
    1 = Mild Stress
    2 = High Stress
  - Does not log category 0.
  - History lookup sorts by loggedAt descending.
  - History limit is clamped between 1 and 250.

Logged document shape:
{
  "stressCategory": number,
  "stressLabel": string,
  "loggedAt": Date,
  "reading": {
    "x": number,
    "y": number,
    "z": number,
    "eda": number,
    "hr": number,
    "temp": number
  }
}


Express middleware in server.js
-------------------------------
The server uses:
  express.json()

It also sets permissive CORS headers:
  Access-Control-Allow-Origin: *
  Access-Control-Allow-Methods: GET,POST,OPTIONS
  Access-Control-Allow-Headers: Content-Type

It serves static frontend files from:
  node-app/public/

It has a single-page fallback:
  app.get(/.*/, ...)

This fallback uses a regular expression because Express 5 does not accept app.get('*')
with the same behavior as older Express versions.


Node API endpoints
------------------
GET /api/health
  Returns:
  {
    "status": "ok",
    "service": "stress-detection-node",
    "inferenceBaseUrl": configuredInferenceUrl
  }

GET /api/telemetry/simulated/latest
  Returns the latest simulated snapshot.
  If no snapshot is ready, returns 503.

GET /api/telemetry/real/latest
  Returns the latest real Firebase snapshot.
  If no snapshot is ready, returns 503.

GET /api/telemetry/next
  Manually advances the simulated CSV cursor, calls Python inference, and returns:
  {
    "sequenceIndex": number,
    "reading": object,
    "predictedStressCategory": number,
    "predictedStressLabel": string
  }

GET /api/telemetry/simulated/history
  Returns MongoDB history for simulated stress events.
  Returns [] if MongoDB is disabled or unavailable.

GET /api/telemetry/real/history
  Returns MongoDB history for real device stress events.
  Returns [] if MongoDB is disabled or unavailable.

History accepts optional:
  ?limit=20


Schedulers in server.js
-----------------------
startSchedulers() runs after the Node app starts listening.

It immediately tries:
  processSimulatedTick()
  processRealTick()

Then it schedules both at the configured interval:
  setInterval(..., STRESS_INTERVAL_MS)

Default interval:
  5000 ms

If Python inference is not running, ticks fail with fetch errors, but the Node server
continues running. Once inference starts, future ticks can succeed.


processSimulatedTick() in server.js
-----------------------------------
Flow:
  1. Get next row from CsvFeed.
  2. Send reading to Python /predict.
  3. Receive stress category.
  4. Create observedAt timestamp.
  5. Append to simulated TelemetryState.
  6. Log to MongoDB if category >= 1 and MongoDB is enabled.
  7. Return snapshot.


processRealTick() in server.js
------------------------------
Flow:
  1. Fetch JSON from Firebase URL.
  2. If there is no data or accX is missing, skip.
  3. Map Firebase fields:
     accX -> x
     accY -> y
     accZ -> z
     gsr -> eda
     pulse -> hr
     temperature -> temp
  4. Convert missing/non-numeric fields to 0.
  5. Send reading to Python /predict.
  6. Append result to real TelemetryState.
  7. Log to MongoDB if category >= 1 and MongoDB is enabled.


predict() in server.js
----------------------
Purpose:
  Calls Python FastAPI inference service.

Request:
  POST {STRESS_INFERENCE_BASE_URL}/predict

Headers:
  Content-Type: application/json

Body:
  { x, y, z, eda, hr, temp }

If inference is unavailable, it throws an error with this instruction:
  Start Python with:
  python -m uvicorn inference_service.main:app --host 127.0.0.1 --port 8081

Known operational notes
-----------------------
1. The Node app can start even if Python inference is not running.
   In that case, scheduled telemetry ticks log fetch failures until Python starts.

2. Full prediction flow requires Python inference running on port 8081.

3. MongoDB is optional.
   If MONGODB_URI is not set, the dashboard still works, but history will show an
   empty message and no stress events are persisted.

4. Real device data depends on Firebase.
   If Firebase is unavailable or missing accX, the real source may not update.

5. The frontend polls every 5 seconds.
   The backend scheduler also processes data every 5 seconds by default.

6. The frontend chart is custom canvas code.
   No external chart library is used.

7. The Node app uses Express 5.
   The catch-all route must use app.get(/.*/, ...) instead of app.get('*', ...).
